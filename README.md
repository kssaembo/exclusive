# 학급용 독점게임 WebRTC 권장 검증판

백엔드와 데이터베이스 없이 교사 브라우저가 공식 게임 상태를 관리하고, 최대 3대의 거래소 태블릿이 PeerJS(WebRTC DataChannel)로 연결되는 정적 웹 프로토타입입니다. 실제 게임 디자인보다 학교 네트워크에서의 연결·동시 거래·복구 검증에 초점을 맞췄습니다.

## 구현 범위

- `/host`: 방 생성, 접속 QR, 거래소 3대 상태/RTT/재접속 횟수, 팀 카드 상태, 시나리오 테스트, 로그, 메시지 품질 결과
- `/station`: 방 접속, 팀과 같은 수의 카드 선택, 거래 요청, 1/10/100회 메시지 테스트, 연결 끊기·중복 재전송·수동 재연결
- 호스트 권위 모델: 모든 거래 검증과 카드 변경은 교사 브라우저에서만 수행
- 동시성: 팀별 버전 검사와 팀 잠금으로 서로 다른 팀 거래는 동시 허용, 같은 팀 거래는 하나만 허용
- 멱등성: `transactionId`별 진행/완료 결과 캐시로 중복 요청의 이중 적용 방지
- 복구: 거래소 지수 백오프 자동 재연결, 화면 복귀/온라인 복귀 감지, 동일 거래소 ID 유지
- 임시 백업: 호스트 공식 상태를 브라우저 IndexedDB에 저장하고 같은 브라우저에서 복원
- 통신/게임 분리: `src/network`와 `src/game`을 분리하여 이후 Firebase 어댑터로 교체 가능

> PeerJS의 기본 공개 시그널링 서버는 두 브라우저가 WebRTC 연결 정보를 교환할 때만 사용됩니다. 카드·거래 상태를 저장하는 백엔드나 DB는 없으며, 실제 게임 데이터는 연결 후 브라우저끼리 직접 전송됩니다.

## 로컬 실행

요구 사항: Node.js 20.19 이상 또는 22.12 이상

```bash
npm install
npm run dev
```

표시된 주소(보통 `http://localhost:5173`)에서 다음 페이지를 엽니다.

- 교사: `http://localhost:5173/host`
- 거래소: `http://localhost:5173/station`

로컬 네트워크의 다른 태블릿에서 테스트할 때는 다음처럼 실행합니다.

```bash
npm run dev -- --host
```

PC의 사설 IP 주소로 접속할 수 있지만, 브라우저/WebRTC 보안 정책 때문에 실기기 검증은 HTTPS가 자동 적용되는 Vercel 배포판 사용을 권장합니다.

## 자동 검사와 빌드

```bash
npm test
npm run build
npm run preview
```

자동 검사는 정상 거래, 서로 다른 팀의 동시 거래, 같은 팀의 충돌 거래, 중복 거래 ID, 오래된 상태 버전을 검증합니다. 빌드 결과는 `dist` 폴더에 생성됩니다.

## 권장 현장 검증 순서

1. 교사용 노트북에서 `/host`를 열고 방 생성 완료(초록)를 확인합니다.
2. 거래소 태블릿 3대에서 QR을 스캔하고 각각 연결됨(초록), RTT가 표시되는지 확인합니다.
3. 각 태블릿에서 메시지 1회, 10회, 100회 테스트를 실행합니다. 호스트에서 수신 수, 누락, 중복을 확인합니다.
4. 호스트의 `정상 거래`, `동시 거래`, `충돌 거래`, `중복 요청` 버튼을 차례로 실행하고 로그 판정을 확인합니다.
5. 실제 태블릿 두 대에서 서로 다른 네 팀을 선택해 동시에 거래하고 둘 다 성공하는지 확인합니다.
6. 실제 태블릿 두 대에서 한 팀이 겹치도록 동시에 거래하고 한 거래만 성공하는지 확인합니다.
7. 거래소에서 `전송 직후 연결 끊기`를 실행합니다. 자동 재연결 후 호스트의 공식 카드 상태로 동기화되는지 확인합니다.
8. 앱을 다른 화면으로 전환했다 돌아오거나 화면을 껐다 켜서 자동 복귀를 확인합니다.

판정 기준 권장안: 100회 전송을 각 거래소에서 5회 이상 반복해 누락·중복이 0이고, 재연결 후 상태 버전과 카드가 호스트와 일치하며, 충돌 거래가 항상 한 건만 반영되면 다음 개발 단계로 진행합니다.

## GitHub 업로드

GitHub에서 빈 저장소를 만든 뒤 이 프로젝트 폴더에서 실행합니다.

```bash
git init
git add .
git commit -m "Add WebRTC validation prototype"
git branch -M main
git remote add origin https://github.com/사용자명/저장소명.git
git push -u origin main
```

이미 Git 저장소인 경우 `git init`과 원격 추가 단계는 생략합니다. 토큰이나 비밀번호를 코드에 넣을 필요가 없습니다.

## Vercel 배포

1. Vercel에서 **Add New → Project**를 선택하고 위 GitHub 저장소를 가져옵니다.
2. Framework Preset이 **Vite**인지 확인합니다.
3. Build Command는 `npm run build`, Output Directory는 `dist`를 사용합니다.
4. 환경 변수는 필요 없습니다.
5. Deploy를 누른 뒤 `https://배포주소.vercel.app/host`에 접속합니다.

`vercel.json`의 rewrite 설정이 `/host`와 `/station` 직접 접속을 Vite SPA로 연결합니다. 배포 주소가 바뀌면 호스트 화면의 QR도 현재 주소를 기준으로 자동 생성됩니다.

## 구조

```text
src/
  game/          # 순수 게임 상태, 잠금, 버전, 거래 ID 중복 방지
  network/       # PeerJS 호스트/거래소 통신 어댑터
  storage/       # 호스트 IndexedDB 백업
  pages/         # /host, /station 화면
  components/    # 상태, 카드, 로그 표시
```

Firebase로 전환할 때는 `GameEngine`의 규칙은 유지하고 `HostNetwork`/`StationNetwork` 대신 동일한 메시지 계약(`WireMessage`)을 사용하는 Firebase 어댑터를 구현하면 됩니다.

## 제한 사항

- 교사 호스트 탭을 닫으면 공식 상태 전송은 중단됩니다. 같은 브라우저에서 다시 열면 IndexedDB 백업을 복원하지만, 거래소는 호스트 복귀 전까지 거래할 수 없습니다.
- PeerJS 기본 시그널링 서버 접근이 학교 방화벽에서 차단되면 방 연결이 성립하지 않습니다.
- 일부 엄격한 NAT/방화벽 조합에서는 TURN 서버 없이 P2P 연결이 실패할 수 있습니다. 이 검증판은 바로 그 현장 가능성을 확인하기 위한 용도입니다.
- 완료 거래 ID 캐시는 현재 호스트 탭의 메모리에 최근 500개만 유지합니다. 공식 서비스 단계에서는 거래 이력의 영속화 정책이 필요합니다.
